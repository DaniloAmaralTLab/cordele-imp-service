# IMP-002 -- Request/Response DTOs + validation pipes

**Status:** INTACT -- gerado 2026-08-24
**Maturidade:** 0 -- Inicial

## Contexto

Define all TypeScript DTO classes used by ImpController as request bodies / response shapes.
DTOs use `class-validator` + `class-transformer` for validation via NestJS `ValidationPipe`.
All schemas are derived from api-contract.md §6 + §8.3.

## Spec de referencia
- SPEC-01 (api-contract.md §6 + §8.3)

## Escopo

Files to create (relative to `backend/src/modules/imp/dto/`):

- `upload-manuscrito.dto.ts` — multipart fields: `projetoId?`, `projetoTitulo?` (exactly one required, validated by custom validator)
- `manuscrito-detail.dto.ts` — response: ManuscritoDetail (id, projetoId, nomeArquivo, formato, status, counts, estrutura, criadoEm)
- `content-tree.dto.ts` — ContentTree schema (schemaVersion, formato, chapters) + Block union types
- `manuscrito-summary.dto.ts` — ManuscritoSummary (without estrutura)
- `segmento-curadoria.dto.ts` — SegmentoCuradoriaDto (manuscritoId, segmentoId, acao, criadoEm, criadoPor)
- `confirm-estrutura-result.dto.ts` — ConfirmEstruturaResultDto (manuscritoId, projetoId, projetoStatus, confirmedAt)

## Resultado esperado

All DTO classes importable by ImpController and use cases. ValidationPipe rejects invalid payloads
at the controller boundary with 400 errors.

## Criterios de aceite

- [ ] `pnpm build` exits 0 with all DTO files present
- [ ] `UploadManuscritoDto` custom validator rejects: `{neither}` → ValidationError, `{both}` → ValidationError
- [ ] `ManuscritoDetailDto` serializes `estrutura` as embedded `ContentTree` object (not string)
- [ ] Unit test for `UploadManuscritoDto` mutual-exclusion validator passes
