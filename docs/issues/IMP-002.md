# IMP-002 — Validação do upload de manuscrito

## Contexto

O endpoint `POST /api/imp/manuscripts` recebe o arquivo e, junto com ele, exatamente um de
dois campos de formulário: `projetoId` (vincular a um projeto existente) ou `projetoTitulo`
(criar o projeto e vincular no mesmo passo). Hoje essa regra só é verificada dentro do use case
de importação. A ideia é que uma requisição inválida seja barrada já na validação do DTO, com um
erro 400 claro em `application/problem+json`, antes de qualquer trabalho do use case.

Os DTOs usam `class-validator` + `class-transformer` com o `ValidationPipe` do Nest. O formato
das respostas está em `docs/services/imp-service/contracts/api-contract.md` (§4.1, §5 e §6).

## Escopo

- `UploadManuscritoDto`: regra "exatamente um de `projetoId` ou `projetoTitulo`" como constraint
  reutilizável do `class-validator`.
- `ManuscritoDetailDto`: `estrutura` sai como objeto `ContentTree` embutido, não como string.

## Checklist

- [ ] `npm run build` passa com todos os DTOs presentes
- [ ] O validador de `UploadManuscritoDto` rejeita a requisição sem nenhum dos dois campos e com os dois
- [ ] `ManuscritoDetailDto` serializa `estrutura` como objeto `ContentTree` (não string)
- [ ] Teste unitário do validador de exclusão mútua de `UploadManuscritoDto`
