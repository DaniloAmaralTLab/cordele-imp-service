## Contexto

Scaffold the NestJS module entry point for Import. The `ImpModule` registers the controller,
use case providers, ports, and all DI tokens. The `ImpController` wires **all 7 routes** —
the 4 original endpoints plus the 3 addendum endpoints (§8 of api-contract.md) — returning
stub responses so that `pnpm build` passes and the smoke route is available before P2 use cases
are implemented.

## Spec de referencia
- SPEC-01 (api-contract.md §4 + §8)

## Escopo

Files to create (relative to monolith root `backend/`):

- `src/modules/imp/imp.module.ts` — registers ImpController, use case providers, port DI tokens
- `src/modules/imp/imp.controller.ts` — 7 routes: POST /manuscripts, GET /manuscripts/:id, GET /manuscripts/:id/estrutura, GET /projetos/:projetoId/manuscritos, POST /manuscripts/:id/segmentos/:segId/ignore, DELETE /manuscripts/:id/segmentos/:segId/ignore, GET /manuscripts/:id/segmentos/ignored, POST /manuscripts/:id/confirm-estrutura
- `src/modules/imp/imp.controller.spec.ts` — unit tests for controller route wiring (stub responses)

## Resultado esperado

`pnpm build` compiles without error. `pnpm test src/modules/imp/imp.controller.spec.ts` passes.
All 7 routes registered under `/api/imp`. DI tokens declared for the 3 use cases and 3 ports.
