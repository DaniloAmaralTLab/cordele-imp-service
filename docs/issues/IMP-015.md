# IMP-015 -- UnparsedSegment detection: all 7 reason types + sourceLocation

**Status:** INTACT -- gerado 2026-08-24
**Maturidade:** 0 -- Inicial

## Contexto

Ensures that both DOCX and Markdown adapters correctly classify and report all 7 reason types.
`rawContent` is always present; `sourceLocation.kind` matches `formato`.
The union of paragraph + image + unparsed nodes must account for the entire source (no silent drop).

This issue is a hardening cross-cut over IMP-013 and IMP-014 — it adds the missing reason
classifiers and the coverage tests.

## Spec de referencia
- SPEC-03 (api-contract.md §6.3 — unparsed-segment taxonomy)

## Escopo

Files to modify:

- `src/infrastructure/parsing/imp/docx-mammoth.adapter.ts` — add detection for: `math_equation` (OMML), `nested_footnote`, `unknown_docx_style`, `embedded_object`, `other`
- `src/infrastructure/parsing/imp/markdown-remark.adapter.ts` — add detection for: `math_equation` (LaTeX), `unsupported_markup`, `other`
- Add unit tests to both adapter specs covering each reason type

## Resultado esperado

For each of the 7 reasons, at least one test fixture triggers it and the UnparsedSegment is
present in the output tree with the correct `reason` and a non-empty `rawContent`.

## Criterios de aceite

- [ ] 7 reason types covered by unit tests: complex_table, math_equation, nested_footnote, unknown_docx_style, unsupported_markup, embedded_object, other
- [ ] `sourceLocation.kind === 'docx'` for DOCX adapter, `'markdown'` for Markdown adapter
- [ ] `rawContent` is never null or empty string on an UnparsedSegment
- [ ] No region of the source is silently dropped (test: total node count matches source paragraph/element count)
- [ ] `pnpm test` on both adapter specs exits 0
